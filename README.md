# Bulong sa Bahay

**The house hears you.** A small first-person Philippine folklore horror game, built in Godot 4.7.2 for browsers and Windows.

Version **0.2.0** is a playable MVP / playtest candidate. This repository contains the source, assets, tests and build tools. Exported games, downloaded tools and test reports are intentionally not committed.

Mika returns to Lola's Southern Luzon home after her funeral. Explore fourteen rooms across two storeys, a courtyard, two staircases and a low crawlspace. An early commitment chooses two different journeys: keep Lola's six wards and quiet candle trials, or restore Tomas's memories, loosen the bindings and burn the pact before escaping. Both endings have skippable, replayable first-person cutscenes. The house reacts to footsteps, doors, and an optional microphone.

## Quick start

### Existing build

From the project folder, run:

```powershell
npm.cmd run serve
```

Open **http://127.0.0.1:8060** after the terminal prints the server address. Leave that terminal running while you play; press **Ctrl+C** in it to stop the server. This serves a previously exported `build/web/` and does not build the game or start Playwright. Internet access is not needed to play once the files are available locally.

### Fresh clone (Windows)

Install Git and Node.js with npm, then run these commands in PowerShell from the folder where you keep projects:

```powershell
git clone https://github.com/RainVar/indiehorror.git
cd indiehorror
npm.cmd ci
powershell -ExecutionPolicy Bypass -File tools/bootstrap.ps1
npm.cmd run build
npm.cmd run serve
```

The first setup downloads the pinned Godot editor and export templates (approximately 1.2 GB for the templates). Later launches only need `npm.cmd run serve` unless you changed the game source. Browser-test downloads are optional and are not needed to play or build.

See [Launching and troubleshooting](docs/LAUNCHING.md) for playing from source, portable Windows builds, changing ports and fixing connection errors.

## Platforms and exports

- Windows: run `build/windows/BulongSaBahay.exe`.
- Browser: serve `build/web/` over HTTP; opening `index.html` directly is unsupported. The single-threaded export uses WebGL 2 and includes landscape touch controls.
- itch.io archives, generated by the build: `build/releases/BulongSaBahay-0.2.0-web.zip` and `build/releases/BulongSaBahay-0.2.0-windows.zip`.
- Source: open `project.godot` in Godot 4.7.2 Standard (not .NET).

The Windows application is portable, x86-64 and unsigned. Android is a browser/touch target, not a native APK release; physical mobile testing is still required. Native Linux and macOS exports are not included. This is an initial playtest candidate; independent first-time playtests and physical Android validation remain release gates. The design targets a 20–30 minute first playthrough, not yet a measured promise.

See [verification results and remaining release gates](docs/QA-REPORT.md) and the [itch.io page draft](docs/ITCH-PAGE.md).

## Controls

WASD/arrows move, mouse looks, **E** interacts, **C/Ctrl** toggles crouch, **Shift** sprints, **F** toggles the flashlight, **J/Tab** opens the journal, **Q** throws the phone, and **Esc** pauses. Hold **E / USE** for 1.5 seconds to commit to a route; hold **E / SKIP** for two seconds to skip a cutscene. Retrieve the phone to reuse it. **F3** shows performance counters.

Touch: drag the lower-left area to move, swipe the right to look, and use the labeled buttons. Landscape is required. A clear rotate prompt appears in portrait; changing to portrait pauses active play.

Browser fullscreen: use the corner button while in a menu. Changing fullscreen or losing mouse capture pauses active play safely; click **Return to the house** to resume mouse look. The fullscreen button hides while the mouse is captured. Press Esc to access menus first.

## Privacy and accessibility

Microphone mode is optional and off by default. Only local loudness is used. No speech recognition, recording, upload, accounts, analytics, or external runtime services are present. Browser denial/disconnect returns to in-game sound mode without losing progress. Use headphones and stay quiet during calibration. Native microphone capture uses Godot's local audio bus; web uses a local Web Audio analyser with explicit track cleanup.

Filipino/English text, sound captions, sensitivity, brightness, volume, touch controls, reduced camera motion, and three quality presets are included. Checkpoint saves use Godot's `user://` storage. Browsers use IndexedDB; private/blocked storage may prevent persistence. Corrupt saves are rejected rather than loaded into gameplay.

## Build and test

The portable toolchain is created in ignored `.tools/`; it is not part of a fresh clone. No global Godot or Blender installation is required when using the bootstrap script. Architecture, foliage, and the creature are authored as code-generated meshes; selected furniture is supplied as GLB assets. `tools/bootstrap.ps1` fetches Godot and templates, verifies official SHA-512 checksums, and recreates the local toolchain. The template download is approximately 1.2 GB; game downloads are much smaller. The Windows build scripts are the supported automated export workflow. Local tooling has been exercised with Node.js 24.21.0 and npm 12.0.2.

```powershell
# Recreate development tools if needed:
powershell -ExecutionPolicy Bypass -File tools/bootstrap.ps1
npm.cmd ci
# Optional: only required for browser automation.
npx.cmd playwright install chromium firefox

# Import, run the gameplay tests, export and package both release targets:
powershell -ExecutionPolicy Bypass -File tools/build.ps1

# Build a separate debug browser export for automation:
powershell -ExecutionPolicy Bypass -File tools/build.ps1 -DebugWeb
node tools/serve.mjs build/qa-web 8061
# In another terminal:
$env:GAME_URL='http://127.0.0.1:8061'
node tests/expansion-web.mjs
node tests/web-resilience.mjs
node tests/save-web.mjs
$env:BROWSER='firefox'
node tests/expansion-web.mjs
# Clear the browser override when finished:
Remove-Item Env:BROWSER -ErrorAction SilentlyContinue
```

The debug automation bridge requires **both** a debug export and `?qa=1`. That QA mode mutes test audio and enables no-capture controls; normal builds keep their audio. The expansion suite uses headless isolated browsers, forbids pointer-lock requests and closes its browsers. Stop the local server with **Ctrl+C** when finished. Release exports have no test bridge. The engine test command disables save writes; screenshots and JSON/XML/HTML reports go under ignored `build/`. Older browser progression scripts are retained as v0.1 diagnostics; `npm run test:web` runs the current expansion suite. These suites expect an already-running server; they do not launch one automatically.

To check the release export, serve it on a separate port and run the safe smoke test in another terminal:

```powershell
# Terminal 1:
node tools/serve.mjs build/web 8062
# Terminal 2:
$env:GAME_URL='http://127.0.0.1:8062'
npm.cmd run test:release
```

The latest recorded results are [52 passing engine tests and successful Chromium/Firefox route checks](docs/QA-REPORT.md). Generated evidence is local, not included in Git. See the [playtest checklist](docs/PLAYTEST.md) for the manual checks still needed.

## Publishing

`npm.cmd run build` imports assets, bakes the house, runs engine tests, exports Web/Windows, and creates the two ZIPs in `build/releases/`. Upload the web ZIP to itch.io as an HTML game with `index.html` at its root; upload the Windows ZIP as the downloadable edition. Preserve the included credits and license files. Follow the [itch.io draft and launch checklist](docs/ITCH-PAGE.md) before making the page public. Pushing this repository does not publish a playable website or create a GitHub Release.

## Project structure

- `scripts/`: world, player, hearing, creature state machine, story, UI, audio and persistence.
- `assets/`: selected CC0 furniture, original textures/audio, OFL fonts, and license texts.
- `tests/`: GdUnit4 gameplay tests plus real browser input, progression, save, touch and microphone checks.
- `tools/`: portable setup, deterministic asset generation, local server and release packaging.
- `docs/`: [launch instructions](docs/LAUNCHING.md), provenance, publishing copy, test summaries, playtest instructions and [player readme](docs/PLAYER-README.txt).

Static box geometry is clipped and baked into material/floor mesh chunks before export. Source edits invalidate the cached shell when running in the editor; release builds load the baked artifact. Boundary walls stay visible; unseen room furnishings and lamps are conservatively culled with a short visibility grace period. Dynamic shadows are restricted to the optional high-quality flashlight. A small 3D A* graph includes ramp links between floors instead of runtime navmesh baking. The audio voice pool is capped at 15. Texture inputs are 256 px, apart from vector artwork and fonts. No network calls occur after local game assets finish loading.

Save schema v2 preserves settings and unlocked endings. Existing v1 runs migrate to the early story fork with their memories, since their old final-choice sequence no longer matches these routes. The original v1 save is left intact. Checkpoints retain completed candle phases and route progress; an ending gallery replay does not change progress.

Architectural surfaces use deterministic material layers and clipped, non-overlapping mesh faces. World textures include mipmaps. See [the surface priority and anti-flicker policy](docs/SURFACE-POLICY.md) for rules, limitations and tests.

Third-party assets and obligations are documented in [the asset manifest](docs/asset-manifest.json) and [credits](docs/CREDITS.txt). Project code and original assets are not assigned an open-source license; third-party assets retain their own licenses. Keep the accompanying license files in distributions.
